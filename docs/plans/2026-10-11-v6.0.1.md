# FreePDF v6.0.1 Implementation Plan

> Execute the authorized implementation and release in this session using the Code and writing-plans workflows.

**Goal:** Publish v6.0.1 with PDF.js as the default, a separate Windows native preview branch and installer, consistent dialogs, truthful progress details, and durable incremental translation.

**Architecture:** Keep one shared application implementation and select the packaged reader through a small tracked build configuration. Translate pages in an isolated worker process, commit a full-length partial PDF after each successful page, and notify the UI with immutable preview snapshots. A stalled worker can be stopped without terminating Qt threads or losing completed pages; matching checkpoints can resume.

**Tech Stack:** Python 3.12, PyQt6, PDF.js, QtPdf, pdf2zh 1.9.11, PyMuPDF, multiprocessing, PyInstaller, NSIS, GitHub Actions, Developer ID signing.

The alternatives considered were merely extending the heartbeat deadline (still loses partial output), modifying upstream converter internals to save partial streams (fragile against upgrades), and translating independent pages with durable checkpoints. Choose the third approach; preserve page count and order, retain original pages until translated, and show that distinction in the progress detail dialog.

### Task 1: Build variants and Windows deployment
- Create `utils/build_config.py`; update `utils/preview_backend.py`, `build.spec`, runtime hooks, installer, build and upload workflows.
- Standard branch defaults to PDF.js; native branch changes only the build configuration and excludes WebEngine libraries.
- Deploy Qt WebEngine libraries/resources/locales/helper and app-local VC runtime dependencies beside the helper. Verify real PDF.js canvas rendering from an installed path containing spaces with an isolated PATH.
- Parameterize packaged smoke checks so a browser recovery does not masquerade as successful PDF.js verification.

### Task 2: Durable incremental translation
- Create `utils/incremental_translation.py`; update `core/translation.py` and translation logging/progress state.
- Save an atomic checkpoint and manifest after each completed page. Publish unique preview snapshots to avoid Windows open-file replacement failures. Use a separate partial filename so incomplete work cannot be mistaken for finished translation.
- Fingerprint the source and settings; resume only matching completed pages. Preserve full page count and original pages that are still pending.
- Bound retries and stop only a stalled worker process after 120 seconds without a service response; keep completed output and explain the remaining original pages. Remove the fixed ten-minute document deadline and unsafe QThread termination.
- Test a multi-page successful job, a failure after page one, cancellation/stall retention, settings/source mismatch, and real engine output in a fresh process with offline HTTP stubs.

### Task 3: UI consistency and progress
- Update `ui/main_window.py`, `ui/components.py`, `ui/theme.py`; create `ui/translation_progress_dialog.py`.
- Center About description, credits, links and version with consistent spacing. Keep footer actions and original main toolbar/panel layout.
- Make status and progress clickable; show stage, current/selected pages, committed page count, service request counts, elapsed/waiting time and a short event history. Update from worker events, never synthesized percentage advancement.
- Keep partial preview and export enabled on failure; do not replace it with an error/loading screen while the next page translates.
- Verify real dialog screenshots, clickable interactions, typography and partial preview behavior.

### Task 4: Documentation and release
- Update Chinese/English READMEs, diagnostics documentation and `docs/releases/v6.0.1.md` with package selection and partial/resume behavior.
- Run all regression tests, both Windows packaged/installed checks, and signed macOS mounted-DMG checks, including a packaged worker translation exercise.
- Publish standard source on main and native source on a `codex/` branch; build each Windows artifact from its verified source revision.
- Create the v6.0.1 Release titled exactly `v6.0.1`, upload standard Windows, native Windows, locally signed macOS and SHA256 checksums, then verify public assets and latest release. Do not notarize, per the user's explicit waiver.
