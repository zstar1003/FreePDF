# FreePDF v6.0.1 预览、翻译与支持日志

主分支及标准安装包默认使用 PDF.js。Windows 原生特别版位于 `codex/windows-native-v6.0.1` 分支，仅将 `utils/build_config.py` 中的 `PREVIEW_BACKEND` 设为 `native`；构建脚本排除 WebEngine，安装包命名为 `FreePDF_v6.0.1_Windows_Native.exe`。标准版遇到浏览器渲染失败时也尝试原生恢复。

之前日志中的 `0xC0000135` 表示 WebEngine 原生子进程无法加载依赖 DLL。标准版在启动钩子中设置随包 DLL、资源和 locale 路径，将 VC 运行库同时放在包根目录及 QtWebEngineProcess 所在目录。原生版直接解除浏览器依赖。实际故障设备仍可能有其他环境差异，不能仅凭这份日志断言某个具体 DLL 丢失。

预览状态中的 `qt_pdf` 表示原生阅读器，`recovery` 记录自动切换原因。`document_loaded` 和 `first_page_rendered` 分别表示文档可读与实际页面渲染完成。

## 逐页翻译与进度

翻译运行在独立进程中。每页实际完成后原子保存部分 PDF 和断点清单，再发送 checkpoint 事件；界面读取独立快照，避免 Windows 阅读器锁住正在更新的文件。服务请求/返回、模型加载、页码、保存和工作进程退出均有日志。段落重试限制为三次，120 秒无服务返回时结束工作进程并保留已提交页面；大型文档没有固定十分钟总截止时间。

点击左下角状态、进度条或百分比可查看详情。重新导入或点击继续会检查源文件 SHA256 与配置指纹，仅恢复一致的断点。清单只存指纹、页码和数量，不保存 API 密钥或段落内容。尚未完成的页保留原文；单页内的中间段落尚未提交为 PDF 页面。

## 导出支持日志

在“关于软件”底部左侧点击“导出日志”，与“检查更新”相邻，选择 ZIP 保存位置即可。日志不自动上传，ZIP 不包含 PDF 或 API 配置；密钥字段及已登记密钥值会脱敏。日志约 5 MiB，保留当前及三份历史文件。

## 发布验证

Windows 两个分支分别验证原生依赖、x64 架构、资源和图标；PDF.js 标准包必须实际完成双栏画布渲染，原生回退不能代替这个检查。原生包检查 WebEngine 文件完全缺席。随后在仅系统 PATH、独立工作目录及含空格的安装路径中验证渲染和真实打包翻译子进程，网络请求使用明确的测试模式替代。Mac 检查本机签名、挂载后的 DMG 以及 PDF.js 实际渲染和打包逐页翻译。
